# Дашборд ИАУ — прототип

🚀 **Живая демо-версия:** https://iau-dashboard-kg.netlify.app

Веб-приложение дашборда Индекса антикоррупционной устойчивости Кыргызской Республики (ИАУ), реализованное на основе методического пособия НИСИ при Президенте КР (2026) и реестра из 57 статистических индикаторов (см. `../docs/DASHBOARD_PLAN.md` и `../docs/INDICATORS_REGISTRY.md`).

## ⚠ Статус данных

Реестр индикаторов, их группировка по 7 функциональным блокам и расчётные формулы соответствуют методике. **Фактические статистические значения по Кыргызстану пока не подтверждены как доступные** (см. `available_in_kg` в `data/indicators_registry.json` — `false` по всем 57 показателям). Поэтому дашборд заполнен детерминированными демонстрационными данными (`src/lib/demo-data.ts`) — это явно отражено баннером в интерфейсе. Как только появится реальная статистика, её нужно будет подключить вместо генератора демо-данных, не меняя расчётный движок и интерфейс (см. раздел «Как подключить реальные данные» ниже).

## Стек

- **Next.js 16 (App Router) + TypeScript** — фронтенд и серверный рендеринг.
- **Tailwind CSS 4** — стилизация.
- **Recharts** — графики (столбчатые диаграммы блоков, линия тренда).
- **d3-geo** — построение SVG-карты регионов Кыргызстана из GeoJSON (серверный расчёт путей, без тяжёлых картографических библиотек на клиенте).
- Данные хранятся в виде типизированных TypeScript/JSON-модулей (без внешней БД) — осознанное упрощение для прототипа; путь к промышленной архитектуре (PostgreSQL, RBAC, реальные интеграции) описан в `../docs/DASHBOARD_PLAN.md`.

## Структура

```
src/
  lib/
    types.ts              — доменные типы (Indicator, Block, EntityRecord, Period, …)
    registry.ts            — загрузка и обогащение реестра 57 индикаторов
    indicator-config.ts     — направленность (позитив/негатив), единицы, Xmin/Xmax по каждому индикатору
    entities.ts             — справочник сущностей: страна, 7 областей, Бишкек/Ош, 10 ведомств
    periods.ts              — справочник периодов (2023–2025)
    calc.ts                 — расчётный движок: нормирование, агрегация блоков и индекса, шкалы интерпретации
    demo-data.ts             — генератор детерминированных демонстрационных значений индикаторов
    compute.ts               — оркестрация расчёта результата по сущности/периоду
    alerts.ts                — правила системы раннего предупреждения
    geo.ts                   — построение SVG-путей карты из GeoJSON (серверный модуль)
  components/               — переиспользуемые UI-компоненты (навигация, карточки, графики, карта)
  app/
    page.tsx                 — Модуль 1: национальная панель ИАУ
    regions/                 — Модуль 2: карта регионов + рейтинг
    agencies/                — Модуль 3: ведомственный рейтинг
    indicators/               — реестр 57 индикаторов (Приложение 1 методики)
    alerts/                   — Модуль 9: система раннего предупреждения
data/
  indicators-registry.json    — реестр 57 индикаторов с привязкой к 7 блокам
  kgz-regions.geo.json         — границы 7 областей КР (geoBoundaries/OSM, winding исправлен)
```

## Расчётный движок

Реализован строго по главе 5 методики:

- `normalizeIndicatorValue` — прямая/обратная нормализация индикатора в шкалу 0–100.
- `weightedAverage` — средневзвешенное значение блока (`Бi = Σ Иij×Wij`) и индекса (`ИАУ = Σ Бi×Wi`).
- `INDEX_LEVELS` / `MAP_ZONES` — 7-уровневая и 4-зонная шкалы интерпретации (п. 5.5 и 7.3 методики).

Веса индикаторов внутри блоков (`Wij`) заданы равными (`1/n`) — официальные веса из Приложения 3 методики не были предоставлены; при их утверждении достаточно обновить `weightInBlock` в `src/lib/registry.ts`.

## Как подключить реальные данные

1. Заменить `src/lib/demo-data.ts` на модуль чтения реальных значений (файл/БД/API), сохранив сигнатуру `getRawValue(indicator, entity, period): number`.
2. Актуализировать `src/lib/indicator-config.ts` (Xmin/Xmax, направленность) по мере утверждения методологии.
3. Обновить `src/lib/entities.ts` и `src/lib/periods.ts` реальным перечнем регионов/ведомств/периодов при необходимости.
4. Убрать/адаптировать баннер `src/components/DemoBanner.tsx`.
5. Для продакшена — перейти на персистентное хранилище (PostgreSQL + Prisma) и добавить формы ввода/импорта данных с верификацией и RBAC, как описано в Этапах 1–2 `../docs/DASHBOARD_PLAN.md`.
